API Testing

How to Test a REST API: A Practical Guide

Learn how to test endpoints, HTTP methods, query parameters, headers, authentication, request bodies and responses without needing a complicated setup.

What is REST API testing?

REST API testing means sending HTTP requests to an API and checking whether the server returns the expected status, headers and data. It is useful when developing, debugging or integrating a web or mobile application.

A typical API request contains a method and URL, and may also include query parameters, headers and a request body.

1. Choose the HTTP method

The method tells the server what operation you want to perform.

  • GET — retrieve data.
  • POST — create or submit data.
  • PUT — replace an existing resource.
  • PATCH — partially update a resource.
  • DELETE — remove a resource.
  • HEAD — retrieve response headers without the response body.

2. Enter the API URL

Start with the endpoint you want to test. For example:

https://jsonplaceholder.typicode.com/todos/1

For endpoints that use query parameters, add them to the URL:

https://api.example.com/users?page=1&limit=20

3. Add headers

Headers provide additional information to the server. Common examples include content type and authorization.

Content-Type: application/json Authorization: Bearer YOUR_TOKEN

Do not publish real API keys or access tokens in frontend source code, screenshots or public repositories.

4. Test authentication

Many private APIs require authentication. A common pattern is a Bearer token:

Authorization: Bearer YOUR_TOKEN

Some APIs use an API key instead. Follow the authentication format documented by the API provider.

Tip: A 401 response usually indicates that authentication is missing or invalid. A 403 response can mean the server understood the request but does not permit the requested operation.

5. Send a JSON request body

POST, PUT and PATCH requests commonly send JSON data. Set the content type and provide valid JSON.

{ "title": "Test", "body": "Hello from API CSV Tools", "userId": 1 }

Malformed JSON can cause the server to reject the request, so validate the body before sending it.

6. Check the response

After sending a request, inspect at least these parts of the response:

  • Status code — indicates the broad result of the request.
  • Response time — helps identify unexpectedly slow endpoints.
  • Response headers — can contain content type, caching and server information.
  • Response body — contains the returned data or error details.

Common status codes

  • 200 OK — request succeeded.
  • 201 Created — a resource was created.
  • 204 No Content — request succeeded without a response body.
  • 400 Bad Request — request data is invalid or malformed.
  • 401 Unauthorized — authentication is required or invalid.
  • 403 Forbidden — the server refuses the requested operation.
  • 404 Not Found — the requested resource was not found.
  • 500 Internal Server Error — the server encountered an error.

7. Test more than one scenario

A good API test is not limited to one successful request. Test valid input, missing fields, invalid values, authentication failures, empty results and unexpected input where appropriate.

  1. Test the normal successful request.
  2. Change or remove required parameters.
  3. Test authentication and authorization behavior.
  4. Check invalid JSON or unsupported values.
  5. Verify that the response structure matches the API documentation.
